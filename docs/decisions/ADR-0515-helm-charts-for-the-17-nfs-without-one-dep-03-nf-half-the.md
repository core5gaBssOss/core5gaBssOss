## ADR-0515: Helm charts for the 17 NFs without one (DEP-03, NF half); the chart config takes compose's environment settings

**Date:** 2026-10-23. **Status:** Proposed.

**Context.** REVIEW-5ae0ef1 DEP-03: CLAUDE.md definition of done item 7 (Docker image + Compose
entry + Helm chart) was unmet for 17 NFs -- CHF, NEF, NSSF, SCP, BSF, ADRF, DCCF, EIR, GMLC,
LI-MDF, LI-MDF3, LMF, MFAF, NSACF, NWDAF, SMSF, UDSF -- and for all of `bss/`. ADR-0513 (PR #42)
gave the 12 existing charts the shape that starts an NF: a generated config ConfigMap at
`/build/config`, the NF's own certs Secret at `/build/certs`, a Service named after the NF.

**Decision:** the 17 NFs get charts in exactly the ADR-0513 shape; the BSS charts and a
`bss/provisioning` image are a separate increment (one subsystem per turn).
- Each chart: `Chart.yaml`, `values.yaml` (image `5gc-<nf>`, `configOverrides`, `certs.secretName`),
  ConfigMap from `files/<nf>.json` (generated by `tools/lab/gen_helm_config.py`, which already
  globs every chart), Deployment (one replica, `enableServiceLinks: false`, config + certs
  mounts), Service named `<nf>`. Secret items are only the files the NF opens (grepped from each
  NF's `CERTS_DIR` paths: CA, its certificate and key, `nrf-jwt/public.pem`; the two MDFs do not
  open `nrf-jwt/`). `scripts/helm/lab-pki-secrets.sh` writes their Secrets unchanged (it globs the
  charts).
- Every port the NF listens on is in the Service, from its lab config and compose: SBI and metrics;
  CHF Diameter 3868/TCP and CAP 2905/**SCTP**; LI_X1 on the CHF (7816), NEF (7815), NWDAF (7817)
  and SMSF (7814) POIs; the MDFs' X1 and X2 (MDF2) / X3 (MDF3). (ADR-0513's charts expose SBI and
  metrics only.)
- ADRF, DCCF, MFAF, NSACF, NWDAF and UDSF register a configured `advertised_ipv4`; each reads
  `<NF>_ADVERTISED_IPV4` first, so their charts set it from the pod IP and the generated file drops
  the key -- the AMF's ADR-0513 rule, now a table for all seven.
- `gen_helm_config.py` applies the compose service's `<NF>_<KEY>` environment values for top-level
  config keys the file has (skipping `${...}` interpolations and the advertised address).
  nf_config reads the variable before the file, so compose ran with values the chart configs
  lacked. This changes: MFAF `event_bus_brokers` (the three internal Kafka listeners), UDSF
  `redis_url`/`redis_mode` (the Valkey Cluster), CHF `quota_model_path`, and -- an ADR-0513 chart
  -- the LI-ADMF's `database_url`, which was left on `127.0.0.1:5439`.

**Rejected alternatives.**
- *One generic chart with per-NF values.* Fewer files, but ADR-0513 chose per-NF charts and
  CLAUDE.md asks for each NF to be deployable on its own; a second chart style would split the
  convention.
- *Writing the env-only settings into config/<nf>.json.* config/ is the host-run config; the
  cluster values (Kafka listeners, the Valkey Cluster) do not belong there.
- *Exposing only SBI and metrics, as ADR-0513 did.* A Service without the X1, Diameter or CAP port
  leaves that listener unreachable by name.

**Disclosed.**
- **Not run in a cluster.** kind, kubectl and helm are not installed on this host now, and the
  host was memory-bound by a CI run. Verified only by `helm lint` and `helm template` (below).
- **Datastores are not provisioned** (as ADR-0513). CHF (Valkey, PostgreSQL, Doris, product
  catalog, balance management), ADRF (Valkey, PostgreSQL, Doris), DCCF, LI-MDF, LI-MDF3 (Valkey),
  MFAF (Valkey, Kafka), NWDAF (Valkey, Doris) and UDSF (Valkey Cluster) exit at startup without
  them (`connect_redis_or_die` / the fail-fast rule); NEF, NSSF, SCP, BSF, EIR, GMLC, LMF, NSACF and
  SMSF need none.
- **The NWDAF MTLF has no chart.** Compose runs the NWDAF image a second time as `nwdaf-mtlf`
  (`NWDAF_ROLE=mtlf`, training sidecar, model volume); the AnLF chart's config still names
  `https://nwdaf-mtlf:7797`. Its own chart (a second role and a persistent volume) is follow-up.
- **SCTP** for the CHF's CAP Service needs a CNI and kube-proxy with SCTP support.
- **The BSS** (`bss/*`, and `bss/provisioning` with no Dockerfile) still has no chart: the next
  DEP-03 increment.
- One replica each: more than one is not verified for any of these NFs in a cluster.
- The ADR-0514 Valkey ACL keys (`redis_user`, `redis_password_file`, the AAnF KEK) are not in these
  charts; they arrive when ADR-0514 (PR #43) and this branch meet in `gen_helm_config.py`.

**Verified (2026-10-23).**
- `alpine/helm:3.16.2`: `helm lint` passes and `helm template` renders for all 17 charts and the
  changed LI-ADMF chart. Each render is a ConfigMap whose data parses as JSON, a Deployment and a
  Service named after the NF, with the ports and pod-IP variables listed above.
- `python3 tools/lab/gen_helm_config.py --check`: 29 chart configs current; no compose container
  IP left in any.
