## ADR-0553: README R19 at-a-glance area table and architecture diagram regrouping

**Date:** 2026-11-02. **Status:** Accepted.

**Context.** The README showed the architecture diagram and a per-NF status table, but no single view of the project's major areas. Those areas are access, control plane, charging, BSS/OSS, AI, operations, LI and the R19 verticals. The user asked for one, placed near the top. The diagram also drew every unbuilt REL-19 family (ADR-0539..0547) in one "R19 completeness" band. That band did not say which tiles were V2X, which were UAS and which were Ambient IoT.

**Decision:**

1. **A "R19 at a glance" section goes into the README, just before the Architecture section.** It is purely additive (guardrail 10). The table between the `r19-areas` markers is generated by `tools/diagrams/gen_readme_areas.py` from `docs/diagrams/architecture.json`. CI runs it with `--check` in the lint job, next to `check_readme_sync.py`.
2. **Every diagram tile belongs to exactly one of 18 areas.** The script fails if a tile is unassigned or assigned twice. As a result, the table's totals always equal the diagram's (46 built, 46 in pipeline at this commit). The counts and tile names are read from the JSON. Only the grouping, the ADR pointers and two status overrides live in the script.
3. **Status vocabulary.** "Partial" is not used (user decision, 2026-11-02). The statuses are:
   - ✅ Built: every tile in the area is built.
   - ✅ Built + 🕒 extensions Already in Pipeline: the area has both kinds of tile.
   - 🕒 Already in Pipeline: no tile in the area is built.
   - 🚧 In progress: set only by hand, and only while an open PR implements the area.
4. **The diagram's single R19 band is split into eight areas:**
   - V2X · A2X
   - UAS
   - Ambient IoT
   - ProSe · 5MBS · sidelink positioning
   - Other 5GC · OAM · media
   - Enablers
   - IMS and messaging
   - Edge

   Each area title names its owning ADR. The canvas grows from 2010 to 2160 px. The SVGs are re-rendered, and a screenshot check found no overlapping labels.
5. **The LI tile is now drawn built,** with source `nfs/li-admf`. LI-ADMF, LI-MDF2 and LI-MDF3 are in the tree and marked ✅ Built in `docs/COMPONENT_STATUS.md` (rows 48–50). Drawing the tile as planned under-claimed them. The tile's text still says that UPF capture is pending. SIRF stays 🕒 Already in Pipeline, as COMPONENT_STATUS row 51 records.

**Disclosed.**

- **"Interconnect and data network (N32 · N6)" is my reading of the user's "Internet connect plane".** It counts SEPP (N32) and the BSS roaming/TAP tile. N6, the UPF's data-network interface, is not counted there: the UPF tile is counted once, under the 5GC control plane, because the diagram draws it there.
- **BSS/OSS is BSS-heavy.** The three tiles are catalog, balance and subscriber management. OSS beyond what the operator GUI and OAM tile cover is thin. The OAM MnS APIs are 🕒 Already in Pipeline (ADR-0547).
- **Positioning counts only what is built,** which is LMF and GMLC. Sidelink positioning keys (SLPKMF) come from ADR-0546. No other R19 positioning item is claimed.
- **Two statuses are hand-written, not derived from the counts:**
  - **Access.** N3IWF/TNGF are in pipeline (ADR-0550) but have no tile yet.
  - **V2X.** It shows 🚧 while PR #80 (PCF V2X, ADR-0551) is open. When PR #80 merges, the override has to be edited by hand. Nothing in CI catches it if that is forgotten.
- **"✅ Built" is a claim about the tiles only.** A built function can still have items deferred for future implementation inside it, for example SEPP N32 items, TSCTSF and AAnF. `docs/COMPONENT_STATUS.md` remains the per-function record.
- **"Other 5GC" and "OAM / media" tiles are counted elsewhere.** UCMF and SoR·MNPF·EIF are counted under the 5GC control plane. The OAM / media tile is counted under Operations.

**Rejected alternatives.**

- **A hand-written table.** Its counts would drift from the diagram, which guardrail 6 forbids.
- **One table row per diagram area.** It would miss the user's areas that cut across diagram areas: interconnect, security, LI and positioning.
- **Counting a tile in more than one area,** for example the UPF under both the control plane and N6. The totals would stop matching the diagram.
- **Keeping one R19 band.** It hid which family each tile belongs to.
