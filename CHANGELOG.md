# Changelog

Notable changes to this project. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and versions follow [Semantic Versioning](https://semver.org/spec/v2.0.0.html): while the version
is 0.x, a minor release may break configuration or APIs. How releases are cut:
[`docs/RELEASING.md`](docs/RELEASING.md). Each architectural change has an ADR in
[`docs/DECISIONS.md`](docs/DECISIONS.md); entries here link the ADR rather than repeat it.

### Changed

### Fixed

- NEF re-encodes the AF id before it puts it into a UDR application-data resource id
  (`iptvConfigData`, `serviceParamData`) or a callback URI, so an encoded `/` or `?` in `afId` no
  longer reaches another resource (ADR-0570 class, NEF part;
  [ADR-0575](docs/decisions/ADR-0575-nef-re-encodes-the-af-id-before-it-builds-a-udr-resource-id.md)).
- The UDM re-encodes request-path values before it builds a UDR URI, so a decoded `/` or `?`
  cannot address another UDR resource
  ([ADR-0570](docs/decisions/archive/ADR-0570-udm-re-encodes-request-path-values-before-it-builds-a-udr.md)).
- The UDR refuses writes for unprovisioned users with 404 `USER_NOT_FOUND`
  ([ADR-0565](docs/decisions/archive/ADR-0565-udr-refuses-writes-under-subscription-data-ueid-for-an.md))
  and bounds its subscription tables per table and per token subject
  ([ADR-0564](docs/decisions/archive/ADR-0564-udr-subscription-tables-bounded-per-table-and-per-token-sub.md));
  the NEF bounds its stores the same way
  ([ADR-0536](docs/decisions/ADR-0536-nef-store-bounds-per-store-and-per-token-sub-ts-29-122.md)).
- `scripts/gen-lab-pki.sh` keeps every existing NF's Valkey ACL user on a partial run; the Helm lab
  Secrets always carry `valkey.password` and the AAnF key, plus a `valkey-users-acl` Secret
  ([ADR-0571](docs/decisions/archive/ADR-0571-valkey-acl-follow-ups-users-acl-keeps-every-nf-helm-secrets.md)).
  `scripts/pipeline-clean.sh` signs in to Valkey as the CHF's ACL user.
- The README append-only check reads its approved-renames list from the base revision, so an
  unstaged approval no longer passes.
- Two review-ledger rows that still said "Open" for work merged in October (SPEC-05 PDU session
  release; NFs registering `127.0.0.1`) are closed; the ransim README no longer says its
  `gnb.yaml`/`ue.yaml` are missing from the repository.

### Security

- The AAnF stores KAKMA sealed with AES-256-GCM under a key-encryption key file, never in the
  clear. In the lab, each NF signs in to Valkey as its own ACL user, and Valkey is no longer
  published on the host
  ([ADR-0514](docs/decisions/archive/ADR-0514-akma-anchor-keys-sealed-at-rest-aes-256-gcm-aanf-key.md)).
  An existing local `certs/` needs `scripts/gen-lab-pki.sh aanf` once, to create the key.
- The AAnF percent-encodes SUPI path segments and replaces an AKMA context atomically
  ([ADR-0549](docs/decisions/archive/ADR-0549-aanf-supi-path-encoding-and-atomic-akma-context-replace-sec.md)),
  and its roaming check fails closed when the UDM cannot answer
  ([ADR-0537](docs/decisions/archive/ADR-0537-aanf-roaming-check-fails-closed-when-the-udm-cannot-answer.md)).

## [0.1.0] - 2026-10-31

The first tagged release. It records the state of the project after its first three months of
development (2026-08-04 to 2026-10-31): a reference implementation that aims at production grade
and is **not deployable in production yet** (see
[`docs/COMPLIANCE_P1_P15.md`](docs/COMPLIANCE_P1_P15.md)).

### Added

- SBI framework (`libs/sbi-core`): HTTP/2 server and client, TLS 1.3 with mTLS, OAuth2 tokens from
  the NRF, `ProblemDetails`, `3gpp-Sbi-*` headers, logging and tracing.
- Code generation of every NF's API from the 3GPP Release 19 OpenAPI YAML (`tools/sbi-codegen`).
- Control plane: NRF, AMF, SMF, UDM, UDR, AUSF and PCF. UE registration and PDU session
  establishment run end to end over real NGAP and NAS.
- User plane: PFCP (N4) and a UPF with an eBPF/XDP uplink GTP-U path. This is a lab fixture, not a
  gNB-facing N3.
- Charging: the CHF of TS 32.290/32.291, with Diameter Gy/Rf, Sy and CAMEL/CAP, verified end to end
  in the lab.
- BSS: TM Forum SID-aligned product catalog (TMF620), subscriber management (TMF632), roaming
  interconnect (TMF651) and balance management (TMF654).
- NWDAF (AnLF and MTLF), DCCF, MFAF and ADRF; AI-assisted quota sizing in the CHF, off by default.
- Release 19 NFs: 10 of 16 Tier 2 NFs, and the SEPP, AAnF and TSCTSF in part. Lawful Interception:
  ADMF, MDF2/MDF3 and IRI-POIs in several NFs.
- Operator console: React and JSON Forms, behind a C++ backend-for-frontend with Keycloak login.
- Lab packaging: Docker Compose and Helm charts, in part.
- Project setup:
  - `NOTICE`, `REUSE.toml` and `LICENSES/`, compliant with REUSE 3.3 (ADR-0507).
  - Display name "AI-Boosted 5G-Advanced Core, BSS and OSS" and a shorter README (ADR-0508).
  - `CODEOWNERS`, area and size labels, Dependabot, OpenSSF Scorecard, Markdown lint and this
    changelog (ADR-0509).
- Helm charts for the 17 NFs that had none (CHF, NEF, NSSF, SCP, BSF, ADRF, DCCF, EIR, GMLC,
  LI-MDF, LI-MDF3, LMF, MFAF, NSACF, NWDAF, SMSF, UDSF), in the ADR-0513 shape
  ([ADR-0515](docs/decisions/archive/ADR-0515-helm-charts-for-the-17-nfs-without-one-dep-03-nf-half-the.md)).

### Changed

- The README is the full project page again, updated for the organization move, licensing and
  process changes, with four stale security-compliance rows corrected
  ([ADR-0511](docs/decisions/archive/ADR-0511-readme-restored-to-the-full-project-page-updated-reverses.md)).
- `README.md` is append/update only: nothing is ever removed from it. Enforced by a pre-commit hook
  and a `readme-append-only` CI job
  ([ADR-0512](docs/decisions/archive/ADR-0512-readme-md-is-append-update-only-nothing-is-ever-removed.md)).

### Removed

- 3GPP and ETSI specification documents, from the tree and from the whole git history
  (ADR-0507). `tools/specs/fetch_3gpp_specs.py --from-manifest` fetches the versions the code
  cites.

### Fixed

- The LI-ADMF Helm chart's database URL pointed at 127.0.0.1; chart configs now take the settings
  compose passes through the environment (ADR-0515).

### Security

- GitHub private vulnerability reporting, code scanning (CodeQL), Dependabot alerts and secret
  scanning with push protection are enabled ([`.github/SECURITY.md`](.github/SECURITY.md)).
